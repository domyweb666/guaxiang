# 瓜相 規矩檔

## 最高標準：結論可信

2026-11-21 多米定。之後所有取捨都照這一條。

- 同一個人連掃三次，結論不變。會跳動的項目不放進報告。
- 每一句都對得到 `rules.json` 的一條規則和一筆量測。
- 量不到就寫量不到。寧可少判，不硬判。

遇到「多判一項」和「這一項還不穩」衝突時，選不判。遇到「畫面好看」和「把沒判的原因寫清楚」衝突時，選寫清楚。

## 鐵則

HANDOFF.md 第二節的十條，任何改動都不准違反。寫程式時最常碰到的三條：

1. 照片、相機畫面、臉部座標、深度資料不離開手機。只有問古書會送文字出去，而且要先勾同意。
2. 沒看的不能算成相符，也不能算成不同。畫面不用勾、叉、合格、不合格。五官要同時寫出三種的數量。
3. AI 不准說規則庫沒有的話。回答裡每一句都要標依據編號，前端要檢查編號存不存在。

## 規則庫和提示詞只有一份

- `rules.json`（repo 根目錄）：網頁版和 iOS 版共用，打包時直接帶進 app。門檻、條文、刻度尺兩端只改這一個檔，不准抄成 Swift 常數。
- `prompt.js`：提示詞的正本。`ios/Guaxiang/Engine/Prompt.swift` 裡那一份要跟它一字不差，CI 會檢查。
- 改了 `rules.json`、`prompt.js` 或網頁版的算法，要重跑 `node ios/tools/make-fixtures.mjs`，Swift 的測試才會拿新的標準答案比。

## iOS 程式的規矩

- 判讀引擎在 `ios/Guaxiang/Engine/`，只用 Foundation，不碰相機和畫面。算法逐行照 `index.html`，改之前先看網頁版怎麼寫。
- 缺哪個量測，用到它的項目就寫沒看。不拿別的點或預設值代替。
- ARKit 的頂點編號不准憑記憶填。量測點一律由 `Engine/MeshLocator.swift` 從網格的形狀找，找完要過合理性檢查，沒過就整組不判（2026-11-24 取代手動對照表，QC-0006）。
- 照片只存一張在這支手機，不上傳、不進備份、匯出不帶、清除資料時一起刪。
- 顏色、圓角、間距寫在 `Design/Theme.swift`，畫面裡不寫裸數字。
- 給人看的字用台灣繁體中文、白話。術語後面用括號解釋。
- Xcode 專案不進 repo，CI 用 XcodeGen 照 `ios/project.yml` 產生。

## 打包和推送

- 改完只 commit、推功能分支。多米開口才打包 TestFlight，不自己推 `main`。
- 這台 Windows 不能編 Swift。推上去之後看 GitHub Actions 的 iOS CI，綠了才算編得過。
- CI 綠只代表編得過、判讀引擎跟網頁版一致。相機、ARKit、Vision、畫面長相都要多米在真機上看過才算數。
