## 第一關：帳號上的準備（你做，最先做）

### 建 app

1. 登入 [App Store Connect](https://appstoreconnect.apple.com) →「App」→ ＋ →「新增 App」
2. 平台選 iOS，名稱填「瓜相」，主要語言繁體中文，SKU 隨便填一個不重複的（例如 `guaxiang`）
3. 套件識別碼（Bundle ID）選 `org.domyweb.guaxiang`。下拉選單沒有的話，先到 [developer.apple.com](https://developer.apple.com/account/resources/identifiers/list) 的 Identifiers 註冊這個 ID，再回來選

名稱「瓜相」如果已經被別人用了，後面加幾個字（例如「瓜相：古書看面相」），到時候告訴我，文案要跟著改。

### 貼四個 secret

到 GitHub 的 `domyweb666/guaxiang` → Settings → Secrets and variables → Actions，新增四個。值跟豆鍵那個 repo 用的一樣，但 GitHub 讀不回來，要重貼：

- `ASC_KEY_ID`
- `ASC_ISSUER_ID`
- `ASC_PRIVATE_KEY`（整個 .p8 檔的內容，貼進去變成一行沒關係，流程會重排）
- `APPLE_TEAM_ID`

### 付費合約

如果第六關決定要收費，「商務」裡的「付費 App」合約要是「有效」。茄記、豆鍵已經在賣了，這個帳號應該簽過，進去看一眼有沒有黃色警告就好。

## 第四關：四件上架前一定要做的驗證

這四件是 HANDOFF 第六節定的，也是瓜相跟一般算命 app 不一樣的地方站不站得住腳。

### 連掃三次（你做）

同一個人、同一個地點連掃三次，再換一天、換光線掃一次。把每次的「匯出數字」傳給我。

結論會跳的項目，我會從報告拿掉或改成「沒判」。這是最高標準「結論可信」的第一條，不能跳過。

### 門檻校準（你收資料、我算）

現在的門檻全部是暫定值，只用測試照片和你的臉調過。要收 50 個人的量測數字，用排名切成 30／40／30。

- 只收數字，不收照片。報告最下面的「匯出數字（不含照片）」就是要收的東西
- 收之前要跟對方說清楚：收什麼、拿來做什麼、不含照片。對方同意才收
- 50 個人用你的手機掃最單純。要讓他們用自己的手機，就得加 TestFlight 測試員，到時候再說

收齊後我重算門檻，改 `rules.json` 的 iOS 那一組。

### 巴納姆盲測（你找人）

找兩個人各掃一次，把報告和問古書的回答對調給對方看。對方看了別人的報告也覺得在講自己，那幾句就要改。把被說「這也是我」的句子抄給我。

### 原文核對（你做）

十二宮、五官的古書原文現在是照通行本，還沒跟善本逐字核對。卡片上有註明。上架前核對完最好；來不及的話，註明留著，送審不會因為這個被擋。

## 第五關：問古書上線

### 部署中繼站（你做）

步驟在 `worker/README.md`，要你的 Cloudflare 帳號和 Anthropic 金鑰。部署完把網址給我，我填進 app（`AskConfig.endpoint`）。

### 次數限制（我做，你定數字）

中繼站現在沒有任何次數限制，誰拿到網址都能一直問，帳單是你的。上架前一定要加。要你定一個數字：每個人每天最多問幾題。我建議 20 題，正常人用不完，被人刷的時候一天的損失也有上限。

中繼站認 app 的方法現在只是一個標頭，誰都能假造。我建議 1.0 就接 Apple 的 App Attest，讓中繼站只收真的從瓜相送出來的請求。這要多寫一段程式，TestFlight 上要多測一輪。

### 30 題評測（我做）

HANDOFF 第七節的評測題：冷讀、健康、重大決定、沒判的項目、誇大、提示詞注入、依據完整。我建 30 題，中繼站部署好之後跑一輪，結果給你看。之後每次改提示詞或換模型都重跑。

這一關沒過，問古書就不放進 1.0。報告本身不靠它。

## 第七關：上架資料

### 隱私權政策網頁（你做，我寫內容）

用到原深感相機的 app 一定要有隱私權政策，而且要寫清楚臉部資料怎麼處理。內容我照 app 裡「設定 → 資料存在哪裡」那一頁寫，你放到 domyweb.org 上，把網址給我。要寫到的四件事：

- 相機畫面、臉部網格、深度資料只在手機上計算，不儲存、不上傳
- 手機裡存的是一張最正的照片和上面的標註位置、量測數字、簡介、問答紀錄，可以一鍵清除。照片在手機鎖著時讀不到，不跟 iCloud 備份走（多米 2026-11-26 定：照片要存）
- 問古書會把文字傳給 Anthropic，要先勾同意；照片和臉部座標不在裡面
- 不拿臉部資料打廣告、不做使用者分析

回饋信箱也在這時候給我，設定頁的「意見回饋」那一列現在是空的。

### App 隱私標籤（你在後台填，照這張表）

| 資料類型 | 填法 |
|---|---|
| 照片或影片 | 不收集（照片只存在手機上，沒傳出去；Apple 的「收集」指傳出裝置，填之前再看一次 Apple 的定義） |
| 臉部資料、其他敏感資料 | 不收集 |
| 其他使用者內容（問古書送出的簡介、問題、量測結果的文字） | 收集；不連結到身分；不用於追蹤；用途選「App 功能」 |
| 其他全部 | 不收集 |

問古書如果沒進 1.0，那一列也改成不收集，app 裡的隱私清單我會跟著改。兩邊要一樣。

### 分級（你在後台填）

瓜相只給滿 18 歲的人用，app 裡也有年齡確認。分級問卷照實填。問卷算出來的分級如果比 18+ 低，後台有把分級往上調的選項就調到 18+。那個畫面我沒看過，到時候截圖給我。

### 類別（你定）

我建議主類別「生活風格」、副類別「娛樂」。算命、星座類的 app 大多放這兩類。放「參考」會讓人以為內容經過查證，跟 app 裡寫的「古書的說法沒有經過科學驗證」對不上。

### 文案和截圖（我寫，你看過才算數）

名稱、副標、關鍵字、描述、截圖上的字，走 `domi-aso-control` 那條線做，另外出一份送審稿。這裡先記瓜相特有的規矩：

- 描述裡不能出現「準」「精準」「科學」「AI 算命」這類字。app 裡寫的是「傳統文化解讀」，上架頁要一樣
- 不寫任何健康、壽命、災禍的字眼
- 截圖至少要有三張能證明這不是罐頭文字：一張有古書原文和出處的卡片、一張「沒判」和原因、一張問古書的回答帶著依據標籤
- 截圖要用真的掃出來的報告，掃的人要同意。不用範例報告的假數字
- 圖上和描述裡不放價格

## 第八關：審查備註和錄影

新 app 第一次送審，茄記和豆鍵都收到 2.1 要求補錄影和說明。瓜相多一層：用到原深感相機的 app，Apple 常會追問臉部資料的五件事。兩份都先備好，第一次送就附上。

### 審查備註（我寫，英文，你看過）

上限 4000 bytes。要寫到的內容：

1. 這個 app 是什麼、給誰用。18 歲以上，掃自己的臉對照古代相書，定位是傳統文化解讀
2. 怎麼操作。打開 → 勾同意 → 掃臉約十秒 → 拉髮際線 → 看報告。需要有原深感相機的 iPhone
3. 跟其他算命 app 哪裡不一樣（回應 4.3(b)）：
   - 用原深感相機量真實的臉部比例，不讓使用者自己選臉形
   - 每個結論都附古書原文、白話和出處
   - 量不到的項目明寫「沒判」和原因，不湊結論
   - AI 回答只能引用這份報告，每一句都標依據，app 會檢查
4. 臉部資料五問：
   - 收集什麼：ARKit 的臉部網格和表情係數，只在掃描當下用
   - 用途：算臉部比例
   - 有沒有給第三方：沒有
   - 存在哪：原始網格、深度、相機畫面不存。手機上留比例數字和一張最正的照片（含 2D 標註位置），不上傳
   - 留多久：原始臉部資料不保留；數字和照片留到使用者按清除，或刪掉 app
5. 外部服務：問古書把文字傳給 Anthropic 的 Claude，要使用者先勾同意，畫面上寫明對象是誰。照片和臉部資料不傳
6. 沒有的東西：沒有帳號、沒有別人看得到的內容、沒有廣告、不接受上傳照片、不做健康判讀
7. 內購：有就寫清楚買什麼、怎麼測；沒有就寫沒有

備註寫什麼，app 畫面上就要是什麼。豆鍵被 4.4.1 退就是 app 裡一句話跟備註打架。送審前我會把備註每一句拿去對畫面上的字。

### 真機錄影（你錄）

- iPhone 更新到最新的 iOS 正式版，裝的是要送審那個 build 的 TestFlight 版
- 開勿擾，從主畫面點瓜相的圖示開始錄
- 一鏡到底：主畫面 → 同意頁打勾 → 相機權限視窗 → 掃臉 → 拉髮際線 → 報告往下滑，點開一個五官、一個「沒判」的宮 → 問古書（勾同意、問一題、點一個依據標籤）→ 設定頁 → 清除所有資料
- 有內購的話，錄到購買和「回復購買」
- 你的臉會在影片裡，這支影片只給 Apple 審查用
- 影片用傳輸線或 icloud.com 拿，不要用 LINE 傳
- 錄完自己從頭看一次。錄的時候發現哪裡壞了就停，告訴我

## 第九關：送審前在真機各走一遍

開發時手上的機器通常權限都開著、網路都通，審查員的不一定。下面每一種都要在 TestFlight 版上走過，一題一項回報我「正常／有問題／沒測」：

- [ ] 相機權限按「不允許」：要看得到說明和怎麼去設定打開，不能黑畫面
- [ ] 飛航模式掃臉：報告要照樣出得來，掃描不需要網路
- [ ] 飛航模式問古書：要顯示問不到，不能一直轉圈
- [ ] 沒勾 AI 同意就按「問」：要擋下來
- [ ] 年紀填 17：要擋下來
- [ ] 沒拉髮際線（按跳過）：三停寫沒判，其他照常
- [ ] 勾紋眉、勾鼻子動過：眉毛、鼻子那幾項寫沒判
- [ ] 清除所有資料：報告、簡介、問答都不見，重開 app 也沒有
- [ ] 深色模式整個流程走一次
- [ ] 沒有原深感相機的 iPhone（有的話）：看顯示什麼
- [ ] iPad：瓜相只做 iPhone，但 Apple 兩次拿 iPad 審豆鍵。手邊有 iPad 就裝 TestFlight 開一次。iPad 的前鏡頭不一定有原深感，至少要顯示「這支裝置不能掃」，不能閃退或卡住
- [ ] 有內購：沒買過的 Apple 帳號、飛航模式各測一次購買畫面

我這邊送審前要做的：

- [ ] 拿掉開發工具：`ios/project.yml` 的 `DEVTOOLS` 那一行。頂點對照、範例報告、貼金鑰都會跟著消失。拿掉後重打一版，你在這一版上重跑上面的清單

- [ ] 版本號定 1.0.0

| 臉部資料（5.1.1、5.1.2） | 追問臉部資料收什麼、存哪、給誰；隱私權政策沒寫到臉部資料 | 備註的五問、隱私權政策那四件事 |

| 1.4.1 健康 | app 裡出現看起來像健康診斷的內容 | 疾厄宮寫「這個工具不判斷健康」；提示詞禁止回答健康。送審前把整個 app 的字搜一遍「病」「壽」「災」 |
| 2.3 文案不實 | 描述寫了 app 做不到的事，或截圖跟實際不一樣 | 描述對這版的 git log 寫；截圖用真的報告 |
| 2.1(b) 內購轉圈 | 審查環境裡 Apple 不回價格，畫面卡住 | 所有 StoreKit 呼叫加 10 秒時限和重試 |
| iPad 上壞掉 | 審查員拿 iPad 開 iPhone 限定的 app | 第九關的 iPad 那一項 |

被退不用急著改程式。先看退件訊息附的截圖，找出審查員看到的是哪個畫面，再決定是補說明還是改 app。
